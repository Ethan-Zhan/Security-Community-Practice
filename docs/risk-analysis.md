# 风险分析记录 (docs/risk-analysis.md)
**课程名称**: 信息安全管理  
**实践项目**: 基于深度神经网络的图像分类服务  
**分析日期**: 2026-05-23  

在基于卷积神经网络（CNN）的图像分类模型向 Web 服务转化的开发前，我们通过第一性原理（First Principles Thinking）深入辨识与评估了该推理模块在信息安全管理上所面临的各项安全威胁。

---

## 一、 敏感操作识别
在深度学习推理服务中，以下操作涉及系统核心资源和物理主机的敏感交互：
1. **API 推理请求发起**：直接调用后端的高性能计算资源（CPU/GPU）与训练模型。
2. **外部文件上传与写入**：客户端上传图片文件并临时/永久保存在物理服务器介质上。
3. **文件名读取与解析**：解析上传文件的文件名以进行存储或结果归档。
4. **模型输入转换**：在内存中对未经验证的二进制数据进行 Pillow 库解码与 Numpy 矩阵转换。
5. **系统错误捕获与回显**：异常情况下的系统报错与应答回显。

---

## 二、 潜在安全风险分析

### 1. 水平与垂直越权漏洞 / 未授权 API 调用风险
*   **风险描述**: 原有算法程序仅在本地运行，未内置鉴权。若转换为 Web API 时没有引入有效的认证授权体系，任何匿名客户端都可任意高频调用该算法接口，造成昂贵的算力资源滥用，甚至泄露私有训练模型的核心参数。
*   **安全危害**: 导致严重的垂直越权，非法调用。
*   **安全控制点**: 身份验证、API 鉴权授权。

### 2. 目录穿越 / 路径遍历漏洞 (Path Traversal)
*   **风险描述**: 图像分类 API 需要读取客户端上传的文件名。如果恶意攻击者伪造文件名（如 `../../../../etc/passwd` 或 `..\..\Windows\System32`），并在没有做文件名安全过滤的情况下直接进行文件路径拼接读取，可能读取或篡改系统关键文件。
*   **安全危害**: 任意文件读取、任意系统写入，破坏主机的完整性与机密性。
*   **安全控制点**: 文件名过滤消毒。

### 3. 上传“图片木马” / 恶意 WebShell 文件注入风险
*   **风险描述**: 恶意攻击者试图将可执行代码（如 Python Webshell 脚本 `shell.py` 或网页木马 `trojan.php`）直接上传至服务器。更隐蔽的是，攻击者可能将脚本代码隐藏在合法的 `.png` 或 `.jpg` 后缀图片文件内（即“图片木马”），以绕过普通的后缀检测，试图在服务器上执行系统命令。
*   **安全危害**: 主机沦陷为肉鸡、恶意远程命令执行、全盘数据泄露。
*   **安全控制点**: 图像二进制流数据合法性校验、后缀白名单机制。

### 4. 拒绝服务攻击 (DoS) - 超大文件上传与处理死锁
*   **风险描述**: 攻击者可以通过分类 API 上传尺寸巨大（如数百兆或分辨率过大）的伪图像，从而导致服务器在对图像进行灰度化与缩放预处理时瞬间耗尽内存（OOM）或 CPU 占用率达 100%，导致正常用户的服务彻底停滞。
*   **安全危害**: 拒绝服务攻击，导致业务连续性中断。
*   **安全控制点**: 上传体积配额限制。

### 5. 调试异常与敏感路径泄露风险
*   **风险描述**: 若程序在解析异常图片文件或推理报错时，直接将 Python 调试堆栈（Traceback）或本地物理盘符路径（如 `D:/github/Security-Community-Practice/...`）原封不动作为 JSON 或 HTML 报错应答返回给前端，攻击者将轻易利用这些泄露的拓扑结构与物理路径组织下一步的针对性攻击。
*   **安全危害**: 敏感信息泄露，为深度渗透提供情报支撑。
*   **安全控制点**: 隐藏报错、统一返回通用错误。

### 6. 对抗性样本攻击风险（机器学习模型独有漏洞）
*   **风险描述**: CNN 模型结构本身对于高频扰动高度敏感。攻击者可以通过给正常的图片施加极微弱的、人眼难以察觉的对抗性扰动（例如快速梯度符号法 FGSM），导致深度学习分类模型以极高置信度给出一个匪夷所思的误分类结果（如将数字 1 识别为 8）。
*   **安全危害**: 模型预测机制失效，损害分类系统的可靠性。
*   **安全控制点**: 输入预处理滤波净化（数据降维/去噪）。

## 三、 安全风险矩阵与评估

| 风险编号 | 识别风险 | 危害等级 | 发生概率 | 缓解策略 |
| :--- | :--- | :--- | :--- | :--- |
| **SEC-01** | 未授权调用与越权风险 | **高 (High)** | 高 | 引入基于 Header 的 API Key / Bearer Token 验证机制 |
| **SEC-02** | 路径遍历攻击 (目录穿越) | **极高 (Critical)** | 中 | 使用 `secure_filename` 强力消毒，强制规范化文件名 |
| **SEC-03** | 图片木马恶意代码注入 | **极高 (Critical)** | 高 | 后缀白名单 + Pillow 图片二进制合法性及结构校验 |
| **SEC-04** | 超大文件 DoS 攻击 | **中 (Medium)** | 中 | 配置 `MAX_CONTENT_LENGTH` 强制物理切断超限文件上传 |
| **SEC-05** | 系统敏感堆栈与物理路径泄露| **中 (Medium)** | 高 | 统一配置全局异常捕获，屏蔽真实报错堆栈 |
