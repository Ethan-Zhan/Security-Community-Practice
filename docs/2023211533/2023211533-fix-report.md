## 二、整改措施

### 整改1：创建安全基础库（includes/security.php）

**问题**：20个关卡各自为战，无统一安全机制。
**修复**：创建 `includes/security.php`，包含：

- `set_security_headers()` — 统一注入5个安全响应头
- `safe_output($data)` — 封装 `htmlspecialchars($data, ENT_QUOTES, 'UTF-8')`
- `log_xss_attempt($level, $payload)` — 记录XSS尝试到日志
- `detect_xss_payload($input)` — 检测常见XSS模式
- 常量定义：`MAX_INPUT_LENGTH=5000`, `SESSION_TIMEOUT=3600`

**改动文件**：`漏洞靶场/includes/security.php`（新增）
**验证方式**：
```bash
php -l 漏洞靶场/includes/security.php  # 语法检查
grep -c "function" 漏洞靶场/includes/security.php  # 确认4个函数
```

---

### 整改2：为所有关卡添加安全头

**问题**：全部20关缺少安全响应头。
**修复**：在每个 level*.php 和 index.php 的 `<?php` 标记后添加：
```php
require_once __DIR__ . '/includes/security.php';
set_security_headers();
```
并确保 `ini_set("display_errors", 0)` 存在。

**改动文件**：`level1.php` ~ `level20.php`，`index.php`（21个文件）
**验证方式**：
```bash
curl -I http://localhost/漏洞靶场/level1.php | grep -E "CSP|X-Frame|X-Content|X-XSS"
```

---

### 整改3：创建安全加固版关卡（hardened/目录）

**问题**：原关卡的漏洞是教学设计的，不能直接删除。
**修复**：创建 `hardened/` 目录，放置修复了漏洞的安全版本：

| 原始文件 | 加固文件 | 修复方式 |
|----------|----------|----------|
| level1.php | hardened/level1_fixed.php | `htmlspecialchars` 转义name输出 |
| level2.php | hardened/level2_fixed.php | input value使用htmlspecialchars |
| level4.php | hardened/level4_fixed.php | 移除str_replace过滤，改用转义 |
| level7.php | hardened/level7_fixed.php | 移除空字符串替换，改用转义 |
| level8.php | hardened/level8_fixed.php | href白名单：只允许http/https |
| level10.php | hardened/level10_fixed.php | 全部hidden input使用htmlspecialchars |
| level11.php | hardened/level11_fixed.php | HTTP_REFERER使用htmlspecialchars |
| level12.php | hardened/level12_fixed.php | HTTP_USER_AGENT使用htmlspecialchars |

**验证方式**：
```bash
# 使用curl测试level1加固版
curl "http://localhost/漏洞靶场/hardened/level1_fixed.php?name=<script>alert(1)</script>" | grep -c "script"
# 预期输出0（被转义后不会出现<script>标签）
```

---

### 整改4：修复htmlspecialchars参数

**问题**：level3等关卡使用 `htmlspecialchars($str)` 而未指定 `ENT_QUOTES`。
**修复**：全局搜索并统一替换为 `htmlspecialchars($data, ENT_QUOTES, 'UTF-8')`。
**改动文件**：level3.php 等
**验证方式**：
```bash
grep 'htmlspecialchars(' 漏洞靶场/level3.php | grep -v ENT_QUOTES
# 预期：无输出
```

---

### 整改5：添加关卡安全注释

**问题**：代码中无安全说明，读者不知道漏洞在哪里。
**修复**：在每个 level*.php 顶部添加注释块，标注漏洞类型、攻击向量、防御方式。
**示例**（level1.php）：
```php
/**
 * Level 1 — 基础反射型XSS
 * 漏洞类型：Reflected XSS (CWE-79)
 * 攻击向量：?name=<script>alert(1)</script>
 * 过滤方式：无
 * 防御措施：htmlspecialchars($name, ENT_QUOTES, 'UTF-8')
 * @see hardened/level1_fixed.php
 */
```

**验证方式**：检查每个level*.php文件头是否包含 `CWE-79` 字样。

## 三、未修复项（教学目的保留）

以下漏洞因**教学目的**有意保留在原关卡的**原始版本**中，在 `hardened/` 目录中有对应的修复版本。

| 保留的漏洞 | 保留原因 |
|-----------|----------|
| Level1 无过滤反射型XSS | 最基础的XSS入门教学 |
| Level2 属性注入XSS | 教授HTML属性上下文的XSS |
| Level4 str_replace仅过滤`<>` | 展示黑名单过滤的不可靠性 |
| Level5-7 多重str_replace绕过 | 展示过滤的逐级升级和绕过技巧 |
| Level8 javascript:伪协议 | 教授href属性中的XSS |
| Level10-13 HTTP头/Cookie注入 | 展示非GET参数来源的XSS |
| Level15 AngularJS模板注入 | 展示前端框架引入的XSS |
| Level17-20 Flash SWF漏洞 | 展示过时组件的安全风险 |

## 四、验证方法总结

1. **语法检查**：`find 漏洞靶场/ -name "*.php" -exec php -l {} \;`
2. **安全头验证**：curl测试每个页面是否有CSP/X-Frame-Options头
3. **加固版功能验证**：对hardened/版本发送XSS payload，确认被转义
4. **原版功能验证**：确保原关卡仍可正常触发XSS（教学功能未受损）
5. **日志验证**：触发XSS payload后检查 `logs/xss_attempts.log` 是否有记录
