## 一、 漏洞整改方案与说明

为了将本地算法脚本 `imageClassification.py` 转化为安全的、能够抵御外部黑客攻击的 Web 预测 API 推理接口，我们实施了以下重大的安全性整改：

### 1. 【越权与未授权访问漏洞整改】
*   **问题描述**: 本地 CNN 图像预测程序不具备鉴权逻辑。如果直接转换为 Web 接口，任何非法外部请求都能滥用算力资源，读取系统预测结果。
*   **整改方法**: 接口统一接入 **API Key 身份校验 (Authorization Header Bearer Token)**。只允许持有合法 Key (`BUPT_SEC_2026_TEST_KEY`) 的客户端进行访问，阻断匿名调用。

### 2. 【目录穿越/路径遍历漏洞整改】
*   **问题描述**: 图像上传和保存逻辑若直接读取客户端传入的 `filename` 进行物理文件处理，极易遭受目录跨越注入（如 `../../etc/passwd`）。
*   **整改方法**: 使用 `secure_filename()` 统一净化和转换上传的文件名，消除所有的绝对路径字符和相对父目录字符，实现完全输入规范化。

### 3. 【大文件 DoS 攻击防范整改】
*   **问题描述**: 深度学习的前处理对 CPU 占用较高。如果攻击者上传特大的图片文件，可能瞬间拖垮服务器，耗尽宿主机内存导致 Crash。
*   **整改方法**: 将 Flask 的 `MAX_CONTENT_LENGTH` 强制锁定在 **2MB**。任何超过该配置的大文件在传输层面就会被 Flask 底层直接切断抛出 413 错误，不进入应用层的业务逻辑处理。

### 4. 【图片木马 / Webshell 文件上传整改】
*   **问题描述**: 攻击者可以通过将恶意代码修改后缀伪装成 `.png` 发送。仅仅比对后缀名无法防御这类的注入攻击。
*   **整改方法**: 在内存数据流对接预处理之前，首先调用 `PIL.Image.open()` 强行对数据进行二进制解码解析并调用 `verify()`，如果是非图片数据流会被立刻捕获并拦截。此外，代码执行**零磁盘落盘存储**（全部在内存中进行前处理与预测），攻击者上传的任何可执行代码都没有留在物理磁盘上并被调用的可能。

## 二、 零配置本地环境验证指南 (测试说明)

> [!TIP]
> **重要测试说明：**
> 为了解决您本地 PyCharm 解释器中缺失 TensorFlow 深度学习庞大环境的问题，我们精心设计了“**自适应兼容模拟技术**”。
> 您在本地测试本 API 时，**完全不需要安装 TensorFlow，也完全不需要下载庞大的数据集！**
> 您只需要有 Python，并安装两个极轻量、极安全的辅助工具（只需数秒钟且绝不会报错）即可。

### 1. 本地测试依赖安装
在您的 Pycharm 终端（或系统命令行）中运行以下指令以安装测试所需的 Flask 服务框架和 Pillow 图片处理库：
```bash
pip install flask pillow
```
*(提示：这两个库加起来仅有几兆大小，安装飞速，不存在任何硬件或 CUDA 版本兼容报错风险。)*

### 2. 启动安全 API 推理服务
双击运行、或在终端命令行中执行启动服务脚本：
```bash
python secure_classification_api.py
```
**启动后的控制台输出展示：**
当检测到您本地缺少 TensorFlow 或没有模型时，控制台将输出醒目的自适应提示：
> `[自适应环境系统提示]: 本地未安装 TensorFlow 库，或加载模型出错。服务已自动为您切换为【安全演示模拟模式（Mock Mode）】！★ 注意：所有的安全拦截防御（API Key校验、防越权、防木马、大文件限制）依然是 100% 真实执行的！`

服务将完美运行并监听在本地：`http://127.0.0.1:5000`
