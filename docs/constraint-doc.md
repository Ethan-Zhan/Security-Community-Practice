# 项目安全约束文档 (constraint-doc.md)

## 1. 背景与基本原则
本项目运行于 GitHub Actions 环境中，所有控制台输出（标准输出 stdout 与标准错误 stderr）皆为潜在的安全暴露面。
* **核心原则**：严禁将任何包含敏感信息（如 Cookie、Authorization Token、用户名、密码、API Key 等）的原始文本直接输出到日志中。
* **处理机制**：所有向控制台的输出必须经过**安全脱敏过滤器**（Sanitization Filter），将敏感数据遮蔽或替换为 `[REDACTED]` 或 `***`。

---

## 2. 约束条件 (Constraints)
在编写或修改自动化签到代码时，必须严格遵守以下技术约束条件：

1. **统一输出入口**：
   * 禁止在代码中直接使用 Python 原生的 `print()` 函数输出未经过滤的外部 API 响应。
   * 必须实现一个统一的安全打印函数（如 `safe_print`），在将字符串输出至控制台前，自动过滤掉已知的敏感关键词。

2. **动态黑名单脱敏**：
   * 脱敏过滤器必须能够动态获取当前环境中配置的所有敏感 Secrets 变量（如从环境变量读取的 `ALPHAGEN_COOKIE`、`CREATIVEHUB_AUTH` 值的片段）。
   * 凡是在输出内容中匹配到这些敏感变量值的部分，必须自动替换为 `[REDACTED_SECRET]`。

3. **异常信息（Exception）安全审查**：
   * 在 `try-except` 块中捕获到异常时，严禁直接打印异常对象本身（如 `print(e)`），因为某些网络库（如 `requests`）在报错中会明文附带请求的 URL（可能含 Token）或 Request Header（含 Cookie）。
   * 仅允许打印经过人工清洗的自定义安全错误提示（例如：“网络连接超时”），若需要打印异常类型，需对异常字符串进行安全过滤后再输出。

4. **禁止第三方响应内容全文打印**：
   * 严禁在接口调用失败时全文打印非 200 状态码的响应文本（`response.text`）。必须使用合理的截断、结构化解析，或仅保留关键状态标志（如解析 JSON 并仅打印返回的错误 Code）。

---

## 3. 禁止行为 (Prohibited Actions)
* **严禁硬编码**：禁止为了测试临时将任何 Token 或 Cookie 字符串作为默认值硬编码在代码、注释或配置中。
* **禁止输出敏感 Headers**：禁止使用诸如 `print(response.request.headers)` 的方式打印完整的请求报头。
* **禁止留有 Debug 残留**：任何开发调试时编写的高风险日志打印，必须在提交 PR 前彻底清理干净。
