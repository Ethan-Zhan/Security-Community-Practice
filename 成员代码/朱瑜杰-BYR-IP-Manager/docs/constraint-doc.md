# BYR-IP-Manager AI 安全约束文档

## 背景说明

目标项目是 Django 编写的 BYR-IP-Manager，核心能力是通过飞书 OAuth 登录后管理用户设备 IP 绑定、设备登录和登出。接口依赖 Django Session 登录态和自定义 `UserInfo` 用户模型。

## 任务范围

本次只加固 `成员代码/朱瑜杰-BYR-IP-Manager` 中与认证、授权、设备绑定、设备管理、外部调用和安全配置相关的代码，并新增对应过程文档与验证报告。

## 必须遵守的安全约束

1. 已登录接口必须以 `request.user` 为唯一授权主体。
2. 客户端提交的 `open_id` 只能作为兼容输入被忽略，不能用于决定操作对象。
3. token 中的用户身份必须与当前登录用户一致，否则返回 403。
4. 状态变更接口不能使用 `csrf_exempt` 绕过 Django CSRF 防护。
5. JSON 请求体必须使用标准 JSON 解析，非法 JSON 或非对象 JSON 返回 400。
6. 数据库写入前必须检查设备是否属于当前用户。
7. 数据库层应提供必要唯一约束，避免同一用户重复绑定相同 IP 或设备编号。
8. 禁止使用字符串拼接和 `shell=True` 执行业务参数。
9. 外部 HTTP 调用必须使用结构化参数、设置 timeout，并检查响应状态。
10. 生产配置必须通过环境变量提供密钥、DEBUG 和 Host 白名单。
11. 服务端异常不能在生产模式下原样返回给客户端。
12. OAuth 回调不能把 `user_access_token` 返回给客户端响应体。

## 禁止行为

1. 不允许为了兼容旧调用继续信任请求体或 query string 中的 `open_id`。
2. 不允许仅通过注释声明安全，必须落实到代码逻辑。
3. 不允许新增硬编码密钥、token 或真实凭据。
4. 不允许扩大改动范围到无关成员代码。
5. 不允许把生成的缓存文件、数据库文件或本地环境文件加入提交。

## 验收标准

1. 伪造他人 `open_id` 不能查看、解绑或验证他人设备。
2. 设备绑定 token 只为当前登录用户签发。
3. 他人 token 即使 IP 匹配，也不能被当前用户验证成功。
4. 静态扫描不再发现目标业务代码中的 `csrf_exempt`、`shell=True`、`demjson3` 或直接读取 `open_id` 决定设备所有者的模式。
5. 新增测试覆盖关键越权场景。
6. 过程材料放置于 `成员代码/朱瑜杰-BYR-IP-Manager/docs/` 和 `成员代码/朱瑜杰-BYR-IP-Manager/reports/`。
